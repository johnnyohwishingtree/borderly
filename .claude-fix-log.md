# Fix Log

## Fix 2 (2026-03-22)

### Problem
Same two tests in `submission-guide.spec.ts` still failing after Fix 1.

### Root Cause
Fix 1 waited for `page.getByText('My Trips')` which matches the **tab bar label** from `MainTabNavigator`. This label appears as soon as `MainTabNavigator` renders (triggered when `loadFamilyProfiles()` sets `isOnboardingComplete: true`), but **before** `loadTrips()` completes. `TripListScreen` calls `loadTrips()` in a `useEffect` — the tab label is visible immediately at mount, before the async trip data loads.

When we then navigated imperatively to `SubmissionGuide`, `useTripStore.trips` was still empty, so `useSubmissionGuide` found no `leg` and couldn't generate a filled form. The loading state persisted.

### Fix
Changed both tests to navigate through the UI to `TripDetail` before navigating imperatively to `SubmissionGuide`:
1. Wait for 'My Trips' tab label (loadFamilyProfiles done → profile set)
2. Click 'Japan Trip' card (only renders after loadTrips() returns → trips populated)
3. Wait for 'Itinerary' in TripDetail (TripDetailScreen also calls loadFamilyProfiles)
4. Navigate imperatively to SubmissionGuide

This mirrors the pattern in `leg-form-action-buttons.spec.ts` which reliably navigates to deep screens.

## Fix 1 (2026-03-22)

### Problem
E2E tests in `[performance]` project failing:
- `submission-guide.spec.ts:46` — mark-as-submitted-button not visible
- `submission-guide.spec.ts:87` — portal info card/step list not visible

### Root Cause
`useSubmissionGuide` hook reads trips from `useTripStore.trips`, which starts as `[]` and is only populated when `loadTrips()` is called by `TripListScreen`. The tests navigated directly to `SubmissionGuide` via `navigateImperatively`, bypassing `TripListScreen`, so the store was empty and the screen stayed in loading state (`!filledForm`).

### Fix
In `e2e/tests/submission-guide.spec.ts`, replaced `page.waitForFunction(() => __navigationRef?.isReady())` with `await expect(page.getByText('My Trips')).toBeVisible({ timeout: 15000 })`. This waits for `TripListScreen` to render (which calls `loadTrips()`), ensuring the trip store is populated before navigating to `SubmissionGuide`. Pattern matches `trip-detail.spec.ts`.
