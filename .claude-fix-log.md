# Fix Log

## Fix 1 — 2026-03-22

### Problem
E2E test `[performance] › e2e/tests/trip-detail.spec.ts:275:7 › TripDetailScreen — Submission Progress (Story #691) › submission progress summary shows 0/N for fresh trip` was failing.

### Root Cause
Playwright's `getByText()` does **substring matching** by default (`exact` defaults to `false`). The TripCard feature added a `"0/2 submitted"` text element (inside `trip-card-submission-indicator`) on the TripListScreen. Since React Navigation keeps the TripListScreen mounted in the DOM while TripDetailScreen is active, both elements existed in the DOM simultaneously:
- TripCard: `"0/2 submitted"` (TripListScreen, behind TripDetail)
- TripDetailScreen: `"0/2"` (submission-progress-summary)

`page.getByText('0/2')` matched both, causing Playwright's strict locator to throw a "strict mode violation".

### Fix
Scoped the locator to the `submission-progress-summary` testID container:
```typescript
// Before
await expect(page.getByText('0/2')).toBeVisible({ timeout: 5000 });

// After
await expect(page.getByTestId('submission-progress-summary').getByText('0/2')).toBeVisible({ timeout: 5000 });
```
