# Fix Log

## Attempt 1 — 2026-03-22

### Root Cause
The `NotificationPermissionScreen` was added to the onboarding flow between `BiometricSetupScreen` and the main app. The `fullJourney.spec.ts` E2E tests had a `completeManualOnboarding` helper and one inline test that expected `My Trips` to appear immediately after clicking "Skip for Now" on the biometric screen — without accounting for the new notification permission screen.

### Fix
Updated `e2e/tests/fullJourney.spec.ts`:
1. Added notification screen skip to `completeManualOnboarding` helper (after biometric skip → wait for `skip-notifications-button` → click it → then expect `My Trips`)
2. Updated the "complete onboarding via demo scan" test with the same two steps (Step 6: notification screen, Step 7: main app)

- `pnpm test` — ✅ 4525 tests passed, 160 suites

## Attempt 2 — 2026-03-22

### Root Cause
`onboarding.spec.ts` tests click "Skip for Now" on `BiometricSetupScreen`, which calls `Alert.alert()`. On web/Playwright this becomes a browser `confirm` dialog. Without a dialog handler, the dialog blocks navigation to `NotificationPermissionScreen`, so the tests couldn't find "Stay on Top of Deadlines".

`fullJourney.spec.ts` already had `page.on('dialog', dialog => dialog.accept())` in `beforeEach`, but `onboarding.spec.ts` was missing it.

### Fix
Added `test.beforeEach` to `onboarding.spec.ts` with `page.on('dialog', dialog => dialog.accept())` so the biometric skip alert is auto-accepted, allowing navigation to the notification screen.

- `pnpm typecheck` — ✅ zero errors
- `pnpm test` — ✅ 4533 tests passed, 160 suites
